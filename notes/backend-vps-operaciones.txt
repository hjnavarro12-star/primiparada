═══════════════════════════════════════════════════════════════════
TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════

El backend no responde (502):
  1. ssh primiparada@187.77.27.122
  2. sudo systemctl status primiparada.service
  3. Si "inactive" o "failed": sudo systemctl restart primiparada.service
  4. Ver por qué falló: sudo journalctl -u primiparada.service -n 50

"SASL: client password must be a string":
  → dotenv no cargó las variables
  → Verificar que .env.production existe en server/
  → El fallback en db.js debería cubrir este caso

"Cannot find module":
  → npm install no se ejecutó en el deploy
  → ssh al servidor y ejecutar:
    cd /var/www/seminario1/primiparada/server && npm install --production

Supabase pausado (BD no conecta):
  → Ver notes/supabase-pausa-reactivacion.txt
  → Reactivar desde el dashboard de Supabase
  → Esperar 2-5 min y reiniciar el backend

Deploy falla en "Upload backend":
  → Verificar que el servidor está accesible por SSH
  → Verificar que SSH_PRIVATE_KEY en GitHub secrets está correcta
  → Reintentar el workflow desde GitHub Actions

ACTUALIZAR BACKEND MANUALMENTE (emergencia)
═══════════════════════════════════════════════════════════════════

Si GitHub Actions falla y necesitas subir cambios urgentes:

  1. Desde la raíz del proyecto, empaquetar:
     tar -czf backend.tar.gz -C server .

  2. Subir al servidor:
     scp backend.tar.gz primiparada@187.77.27.122:/tmp/

  3. En el servidor:
     ssh primiparada@187.77.27.122
     cd /var/www/seminario1/primiparada/server
     tar -xzf /tmp/backend.tar.gz
     npm install --production
     sudo systemctl restart primiparada.service

  4. Verificar:
     curl https://primiparada.seminario1.eleueleo.com/api/health
